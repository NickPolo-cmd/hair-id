# Как выложить сайт на GitHub Pages

Netlify отказывается публиковать («Account credit usage exceeded»), поэтому
сайт собран под GitHub Pages. Оба сайта поедут одним репозиторием:
студия в корне, магазин в папке `shop`.

**Важно с самого начала: репозиторий будет публичным.** Бесплатный GitHub Pages
из закрытого репозитория сайт не отдаёт. Значит, всё, что попадёт в коммит,
сможет прочитать любой человек по ссылке, а вычистить это потом можно только
переписыванием истории. Что именно не публикуется — в разделе ниже.

---

## Шаг 1. Собрать сайт под ваш адрес

Уже собрано под ваш логин. Пересобирать нужно только после правок сайта:

```bash
cd ~/Desktop/Волосы && node tools/сборка-для-github.mjs https://nekitshit.github.io/hair-id
```

Команда создаёт папку `docs/` и переписывает в ней все адреса: и в ссылках,
и в `canonical`, и в разметке для поисковиков, и в `sitemap.xml`. В конце она
печатает, сколько ссылок переписала и не осталось ли старых.

Адрес обязательно с `https://` в начале. Chrome в адресной строке протокол
прячет, и скопированный оттуда адрес приходит голым — на такой сборке ссылки
становятся относительными и каждый переход даёт 404. Скрипт теперь сам это
ловит и отказывается собирать.

Репозиторий должен называться **hair-id** — под этот адрес всё собрано.
Если назовёте иначе, пересоберите командой выше с новым именем.

---

## Шаг 2. Создать репозиторий и отправить файлы

```bash
cd ~/Desktop/Волосы && git init && git add -A -n > /tmp/проверка.txt
```

Прежде чем коммитить, убедитесь, что закрытое не уходит:

```bash
grep -cE "поставщик/|товары-цены|graphify-out|\.playwright-mcp|ФОТО-И-ВИДЕО|фото-инфографика" /tmp/проверка.txt
```

Должно напечатать **0**. Если больше нуля — не коммитьте, сначала разберитесь,
какое правило в `.gitignore` не сработало.

```bash
cd ~/Desktop/Волосы && git add -A && git commit -m "Сайт Hair ID: студия и магазин"
```

Дальше создайте на github.com пустой репозиторий с именем **hair-id**
(без README и без .gitignore) и выполните:

```bash
cd ~/Desktop/Волосы && git branch -M main && git remote add origin https://github.com/nekitshit/hair-id.git && git push -u origin main
```

---

## Шаг 3. Включить Pages

В репозитории: **Settings → Pages → Build and deployment**.

- Source: **Deploy from a branch**
- Branch: **main**, папка **/docs**
- Save

Через минуту-две сайт открывается по адресу из шага 1.

---

## Что попадёт в репозиторий, а что нет

Репозиторий публичный, поэтому в `.gitignore` вписано всё, что читать посторонним
незачем:

- **папка `поставщик/` и `товары-цены.txt`** — контакты фабрик, переписка,
  закупочные цены и разбор рисков по товарным знакам. Файлы остаются у вас
  на диске, просто не публикуются;
- **исходные фотографии**: 77 снимков от вас (12 МБ), прозрачные PNG товаров
  (19 МБ), снимки экрана сайта (26 МБ), фото и видео для Авито (65 МБ);
- **рабочие данные бота** и его журналы;
- **служебное**: граф знаний проекта `graphify-out/` (8 МБ), дампы страниц
  из браузерной панели `.playwright-mcp/` (туда попадают данные из форм),
  два отладочных снимка шапки.

Внутренние записки в сборку тоже не идут: файлы `ИСТОЧНИКИ.md` и
`ФАКТУРЫ-И-КОД.md` лежат рядом с фотографиями и объясняют, что снимки стоковые,
а лицо мастера на них чужое. На живом сайте это читалось бы по прямой ссылке,
поэтому сборщик все файлы `.md` пропускает.

Ключей и токенов в проекте нет: и токен бота, и ключ OpenRouter лежат вне папки
проекта, в системных файлах. Проверено поиском по всем файлам перед выкладкой.

Файлы `_headers` в сборке остаются, но на GitHub Pages не работают: это формат
Netlify. Свои заголовки ответа на GitHub Pages задать нельзя ничем — заголовки
`Referrer-Policy` и `X-Content-Type-Options`, которые сайт отдавал на Netlify,
там просто не отдаются. Файлы не удаляем: пригодятся, если сайт вернётся
на Netlify.

## После первой публикации

1. Откройте сайт и проверьте, что переходы между студией и магазином работают.
2. Проверьте с телефона — не только с компьютера.
3. Если решите завести свой домен (например `hairid.рус`), в настройках Pages
   есть поле Custom domain; после этого сборку надо прогнать заново уже
   с новым адресом, одной командой из шага 1.
   При подключении домена GitHub сам добавляет в `docs/` файл `CNAME` — не
   удаляйте его. Сборка его сохраняет, но если он всё-таки пропадёт из коммита,
   GitHub снимет домен и сайт по нему открываться перестанет, пока вы не введёте
   домен в настройках заново.
4. Отправьте карту сайта руками — сама она не найдётся. Роботы читают
   `robots.txt` только из корня домена (`nekitshit.github.io/robots.txt`),
   а наш лежит в подпапке `/hair-id/` и не запрашивается вовсе. Поэтому
   в Яндекс.Вебмастере и Google Search Console добавьте ресурс с префиксом
   `https://nekitshit.github.io/hair-id/` и отправьте карту
   `https://nekitshit.github.io/hair-id/sitemap.xml`. Страницы магазина в неё
   уже включены — сборщик сводит обе карты в одну, потому что здесь студия
   и магазин живут на одном домене.

## Когда что-то поменяли на сайте

```bash
cd ~/Desktop/Волосы && node tools/сборка-для-github.mjs https://nekitshit.github.io/hair-id && git add -A && git commit -m "Правки сайта" && git push
```

Правки всегда вносятся в `site/` и `site-shop/`, а `docs/` пересобирается
командой. Править файлы прямо в `docs/` не нужно — они перезаписываются.
